binary_upgrade_set_next_pg_type_oid

定義

  • 種別: function
  • 定義箇所: src/backend/utils/adt/pg_upgrade_support.c:52

目的

pg_upgrade 実行時、次に作成されるデータ型（pg_type）の OID を強制的に指定するために使用されます。

シグネチャまたは形状

Datum binary_upgrade_set_next_pg_type_oid(PG_FUNCTION_ARGS)

入力と出力

  • **入力**: PG_GETARG_OID(0) を介して、次に割り当てるべき OID を受け取ります。
  • **出力**: void（PG_RETURN_VOID() を返します）。

前提条件と不変条件

  • サーバーが binary_upgrade モードで起動されている必要があります。CHECK_IS_BINARY_UPGRADE マクロにより、この条件が満たされない場合はエラーが発生します。

アルゴリズムまたは振る舞い

1. 引数から OID を取得します。 2. CHECK_IS_BINARY_UPGRADE を実行し、アップグレードモードであることを検証します。 3. グローバル変数 binary_upgrade_next_pg_type_oid に取得した OID を代入します。 4. 処理を終了します。

呼び出し元と呼び出し先

  • **呼び出し元**: src/bin/pg_dump/pg_dump.c から SQL コマンドとして呼び出されることが確認されています。
  • **呼び出し先**: 内部的なグローバル変数への代入のみであり、他の関数呼び出しは行われません。

関連データ構造

  • binary_upgrade_next_pg_type_oid: catalog/binary_upgrade.h で定義されたグローバル変数。

失敗モードと境界条件

  • binary_upgrade モード以外で呼び出された場合、CHECK_IS_BINARY_UPGRADE によりエラーが発生します。

保守担当者向けメモ

  • 本関数はシステムカタログの整合性を直接操作する強力なツールです。誤った OID を設定するとカタログの不整合を招くため、pg_upgrade 以外のコンテキストでの利用は想定されていません。
